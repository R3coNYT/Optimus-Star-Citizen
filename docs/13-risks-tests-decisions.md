# Risks, test strategy and technical decisions

## 13.1 Technical risks

Rating: **P** probability (1–5) × **I** impact (1–5).

| # | Risk | P | I | Score | Mitigation | When it is cleared |
|---|---|---|---|---|---|---|
| ~~R1~~ | ~~**`SendInput` injection ignored or filtered by Star Citizen**~~ → **RISK CLEARED on 2026-08-24** | — | — | — | **Star Citizen reacts to scancode `SendInput` injection**, as a standard user, without elevation (S0-1/game, R3CON-PC). Plan A is validated; plans B (the Interception driver) and C (an emulated HID) are dropped. The rule of conduct remains: never continuous automation, one utterance means one deliberate action. | ✅ done |
| ~~R2~~ | ~~**STT latency outside budget**~~ → **RESOLVED on 2026-08-25 by spike S0-6** | 1 | 5 | **5** | The budget is met by a **constrained-grammar recogniser** instead of a general-purpose transcriber: **16.7 ms p50, 27.2 ms p95, 21/21 commands correct**, with no GPU and no download (D28). | **R16** | **Smart App Control blocks unsigned executables** — **hit on 2026-08-25** | 5 | 4 | **20** | Observed on R3CON-PC: “An application control policy has blocked this file.” On by default on some Windows 11 installations, and **Windows does not allow it to be turned back on once disabled**: working around it by switching it off is not an acceptable thing to ask of a user. A development workaround: a framework-dependent publish launched by `dotnet.exe` (signed by Microsoft) — **but it is not enough**. On 2026-08-25 a second occurrence hit the DLL itself (`0x800711C7`), when the same command had worked the day before: the policy evaluates **every file**, and any publish produces one with a fresh hash. The block is therefore structural and intermittent, not accidental. `tools/diagnose-app-control.ps1` separates the two lookalike causes — a mark of the web inherited from a USB copy, which lifts without disabling anything, and SAC being active, against which no file manipulation can do anything. **The cause of the second occurrence was identified and lifted on 2026-08-25**: the global keyboard hook introduced by the keybind editor. Replacing it with the console's input buffer (D36) unblocked the publish on a machine where SAC is nonetheless **active** — which teaches that the policy judges the content, not only the signature, and that a sober binary gets through where one behaving suspiciously fails. **Measured on 2026-08-26** by reading the `CodeIntegrity/Operational` log: only **entry-point** assemblies are refused — `Optimus.App.dll`, `Optimus.Cli.dll` and their apphosts. `Optimus.Core.dll` and `Optimus.Infrastructure.dll`, which does contain `SendInput`, are never evaluated. So it is not what Optimus does that makes it suspect, but its lack of reputation. **A corollary: launching through `dotnet.exe` is not enough** — the entry assembly is evaluated the same way, and that workaround, which had seemed to work, was refused in turn. There is therefore no packaging workaround. **Lifted on the gaming machine on 2026-08-26**: the user disabled Smart App Control, knowing the operation is irreversible. The risk no longer blocks development, but it remains whole for any distribution — and it will come back intact on that machine after a Windows reinstall. **Route chosen on 2026-08-27: the SignPath Foundation**, which signs open source projects for free. It is preferred not out of convenience but because the others cost between €100 and €600 a year, which is out of budget for this project — and a certificate you fail to renew leaves a binary signed by an expired key, which is worse than nothing. In return it requires a public repository, an OSI licence, and a build from source on a public CI: **it is therefore as much a distribution decision as a technical one** (see 13.5). Rejected along the way: a self-signed certificate, worthless to SmartScreen since every user would have to install the root in their trust store — a bigger ask than the warning it claims to avoid. **Timing: after the feature worksites**, at the maintainer's request on 2026-08-27. The work to do then: publish the repository, choose the licence, set the build up in GitHub Actions, submit the SignPath application, then wire signing into `tools/build-installer.ps1`. It covers the executable **and** the Inno Setup installer | **Before distribution, after the feature worksites** |

> **R14 is the project's highest risk.** The brief describes an ambitious platform; the only way to
> reach it is to ship a narrow, excellent MVP and then widen.

## 13.3 Test strategy

### Unit tests (fast, no hardware)

| Target | Critical cases |
|---|---|
| `TextNormalizer` | accents, elisions, spelled-out numbers, punctuation, filler words, the wake word |
| `FastIntentMatcher` | exact, fuzzy, thresholds, ties, disabled commands, **regression protection over 200 reference phrases** |
| `BindingResolver` | missing binding, empty binding, conflict, actionmap, modifiers |
| `SequenceRunner` | order, delays, `repeat`, `if`, **guaranteed release on exception or cancellation** |
| `PersonalityEngine` | trait filtering, anti-repetition, forbidden phrases, word budget, determinism under a fixed seed |
| `ExecutionGuard` | kill switch, simulation, focus, cooldown, `dangerous`, permissions |
| `ScActionMapImporter` | empty XML (**the real case of `layout_Keybinds_1_exported.xml`**), deltas, `input=" "`, combos, malformed XML |
| Schema validation | an invalid catalogue ⇒ the item is disabled, the app starts, the error is surfaced |
| Permissions | the Discord/API/plugin matrix |

### Architecture tests (NetArchTest, blocking in CI)

```
✗ No type outside Optimus.Infrastructure.Input references SendInput / VK_* / scancodes
✗ Optimus.Core references neither PresentationFramework, nor System.Windows, nor Discord.Net
✗ No *.Ai.* project references *.Input.*
✗ No literal key string in Optimus.Core (a dedicated Roslyn analyser)
✗ Every public type in Optimus.Sdk is documented (XML doc required)
```

### Integration tests

STT against reference WAVs (30 sentences, 3 speakers, with and without background noise) ·
TTS (available voices, synthesis, fallback) · SQLite (migrations forwards and back) ·
SC XML import (file sets from several versions) · the API (auth, scopes, rate limit) ·
Discord (permissions, pairing, revocation) · a test plugin (loading, crashing, unloading).

### End-to-end tests (simulation mode, without the game)

```
WAV “optimus open the doors”
  → the whole pipeline with SimulatedInputEngine
  → assertion: intent = ship.doors.toggle, binding = L, result = simulated
  → assertion: the budgeted latency is met
  → assertion: the reply matches the character, with no forbidden phrase
```

**35 scenarios** covering: success, missing binding, game absent, game not in the foreground,
cooldown, kill switch during a sequence, disambiguation, a pending slot, a `dangerous` command
confirmed and refused, an unknown phrase, a failed provider, a missing plugin.

### Manual tests (a release checklist, in game)

Real injection windowed and full screen · perceived latency · measured FPS impact · a long session
(8 h) · unplugging the microphone · changing the audio device · updating the app mid-session · a
clean uninstall.

## 13.4 Recommended technical decisions — summary

| # | Decision | Alternative rejected | Reason |
|---|---|---|---|
| D1 | C# / .NET 8 + WPF, a single process | Tauri, Electron, Python/Qt | Audio + P/Invoke + footprint + project risk |
| D2 | Local STT with Whisper.net by default | cloud by default | Offline, no cost, privacy (§84) |
| D3 | Windows OneCore TTS by default, Piper optional | ElevenLabs by default | Works immediately, with no account and no cost |
| D4 | **LLM off by default** | an LLM at the heart of the pipeline | §84–85: determinism, latency, cost, privacy |
| D5 | A deterministic local matcher in the front line | everything to the LLM | ~300 ms vs ~1,500 ms, and testable |
| D6 | `action_id` modelled on Star Citizen's actionmaps | in-house identifiers | Import, diff and migration become trivial |
| D7 | Configuration in JSON files, runtime in SQLite | everything in the database | Diffable, repairable, shareable |
| D8 | `ExecutionGuard` = the single point of control | checks scattered around | One place to audit |
| D9 | Simulation mode from day one | added later | Makes development and testing possible without the game |
| D10 | A mandatory global kill switch | an option | Basic safety for an app that drives a keyboard |
| D11 | A **local** Discord bot by default | a central bot | Isolation by construction (§81–83) |
| D12 | Plugins in an `AssemblyLoadContext` + permissions | free loading | Resilience and safety |
| D13 | Velopack for installation and updates | MSIX, Squirrel | Simple delta updates, no store constraints |
| D14 | Models downloaded after installation | embedded | A light installer, a choice of size |
| D15 | An immediate acknowledgement beep | nothing | The project's best ratio of perceived effect to effort |
| ~~D16~~ → **D30** | **Always listening by default**, with the wake word required at the head of the grammar; push-to-talk as a choice, on a configurable key | ~~PTT by default~~ | **Decision revised on 2026-08-25.** PTT was the obvious choice as long as the STT was Whisper: it transcribes *everything* it hears, which raised a privacy problem and false triggers. With the grammar engine (D28), always-on listening becomes structurally safer: the grammar only accepts sentences **starting with the wake word**, and ordinary conversation matches no alternative — it is rejected by construction, without having been transcribed. Both modes stay on offer, set in the user profile |
| D17 | Categories as a validated closed enumeration | free strings | Avoids exactly Jean-Bot's `category.id` bug |
| D18 | An end-to-end `trace_id` | independent logs | Support becomes possible |
| **D19** | **A fixed scancode table in US positions; `MapVirtualKey` banned from the engine** | conversion through the active Windows layout | **Measured in spike S0-1**: on AZERTY, `MapVirtualKey(VK_A)` returns `0x10` (the `Q` position) when Star Citizen's `kb1_a` is `0x1E`. A layout-dependent conversion sends the wrong key for most French-speaking players. Prototype of the table: `tools/Optimus.Spike.InputTest/src/ScanCodes.cs` |
| **D20** | **`timeBeginPeriod(1)` active while a sequence runs** | `Thread.Sleep` alone | Without it the granularity is about 15 ms; with it, holds are accurate to ±1.4 ms (measured, S0-1/T4) |
| **D21** | **`hold_ms` derived per action from Star Citizen's `activationMode`**, with 45 ms as a floor | a global constant | The game **declares its own** 18 activation modes and their thresholds in `defaultProfile.xml`. A `delayed_press` needs ≥ 0.25 s, a `delayed_press_medium` ≥ 0.5 s, a `delayed_hold_long` ≥ 1.5 s: **31 actions out of 627 would fail silently** with a 45 ms tap. The 45 ms floor comes from S0-1/G3 (the game accepts 16 ms) |
| **D28** | **Two-tier STT: a constrained grammar for commands, Whisper for conversation** | Whisper alone for everything | Measured (S0-6) on the same recordings as S0-2: **16.7 ms against 3,336 ms**, and 21/21 commands correct. A grammar engine can only produce an allowed sentence — “boucliers” cannot become “bouquilles” if the word is not in the grammar. Using a general-purpose transcriber to choose among 59 possibilities known in advance was the wrong tool. `ISpeechToTextProvider` made the change painless |
| **D29** | **Two thresholds: noise below 0.35, execution from 0.65, a proposal in between** | a single threshold at 0.40 | **Recalibrated at the microphone on 2026-08-25**, the file-based bench having lied: recorded audio produces lower confidences than a live microphone. Real measurements — ambient noise 0.00–0.06 · commands 0.69–0.93 · out-of-catalogue phrases 0.51–0.64. But the bands **overlap** (a valid command came down to 0.55), so no single threshold is enough: inside the interval, Optimus offers the command and waits for “Optimus, confirm” for 12 s. Refusing a valid command is as annoying as running an unasked one |
| **D31** | **Questions to the copilot are catalogue commands**, not errors to filter out | treating “who are you?” as off-topic | Observed at the microphone: “Optimus, who are you?” was pulled onto `system.cancel`. A grammar engine always returns its best alternative — if the legitimate question is not in it, it names another one. The remedy is not to harden the filter but to **enrich the catalogue**: `dialogue.identity` and `dialogue.wellbeing` now get 0.69 and 0.91 confidence |
| **D32** | **No figure about the ship's state until it is measured.** The `system.status` lines stay avowed set dressing until an `IGameStateProvider` arrives | reciting plausible readings for want of better | **Decided on 2026-08-25.** “Reactor nominal, shields at one hundred percent” sounds good, but Optimus has no telemetry: it is an invented reading, delivered with the assurance of a measurement. As long as it is atmosphere, it passes; the day a pilot relied on it in flight, a false figure would be worth less than silence. The set dressing is therefore kept **for now**, and these lines will be the first rewritten when telemetry exists — not the last. See the note in `responses.fr.json`, which carries the same warning next to the texts concerned |
| **D33** | **The requested direction is part of the intent**, carried from the grammar all the way to execution. A directed sequence when the game declares one and it has a key; a toggle with an assumed state otherwise | treating “turn off” as a synonym of “turn on” | **Decided on 2026-08-25**, on request. Almost everything in Star Citizen is a toggle: one key that inverts. “Turn off the lights” therefore sent the same key as “turn on”, and turned them off half the time. The game does declare 16 directed actions (`v_lights_on`/`v_lights_off`) — **none has a default key**, which gives the keybind editor its second reason to exist. In the meantime Optimus falls back on the toggle and trusts what it switched itself (see [[ToggleBelief]]). That belief is fallible — the pilot can act at the keyboard — hence the escape hatch: **asking for the same thing again overrides it**. A false belief costs one round trip, never a deadlock |
| **D34** | **The inclusion score is governed by coverage**, with no floor above the execution threshold | a floor of 0.90 for any contained phrase | **Fixed on 2026-08-25.** The formula `0.90 + 0.08 × coverage` placed every inclusion above the execution threshold (0.85): an isolated word claimed any utterance containing it, and “priority to weapons” toggled the armament at 0.93. The code comment nonetheless claimed the score decreased with the extra words — it did not. It is now `0.72 + 0.26 × coverage`: one word in three drops to 0.81, and therefore into the proposal band. Found while writing the test that was supposed to prove the nested phrases flagged by the validator were harmless |
| **D35** | **The keybind editor writes on both sides**: an assignment layer for Optimus, and a mapping file Star Citizen can read back | recording the key only on Optimus's side | **Decided on 2026-08-25.** Optimus sends keys, it does not talk to the game: assigning `K` to the doors on Optimus's side produces nothing until Star Citizen also associates `K` with `v_toggle_all_doors`. An editor filling only the Optimus half would be a placebo — the user would see an assigned key and a command that does not work, with no way to understand why. Hence both directions: `--import-layout` learns what the pilot already set in the game, `--export-layout` produces the `ActionMaps` to load with `pp_RebindKeys` |
| **D36** | **Key capture reads the scancode from the console's input buffer**, never from a global keyboard hook and never from the virtual key code | `SetWindowsHookEx(WH_KEYBOARD_LL)`, or `Console.ReadKey` | **Revised on 2026-08-25, the same day.** Two requirements stack up. First the scancode: this is D19 seen from the other end — on AZERTY, the key marked “A” carries the virtual code `A` but occupies the US `Q` position, the only one the game and the injection know; capturing by virtual code would record one key and press another, and it *would look* right. Then the scope: the first implementation used a low-level hook, which intercepts keystrokes from **every** application in order to read a single key meant for this one. Disproportionate, and it is the signature of a keylogger — the first publish containing one got blocked by Smart App Control, where the previous ones went through (R16). `KEY_EVENT_RECORD.wVirtualScanCode` gives the same scancode without seeing anything not addressed to us |
| **D37** | **A macro names commands and a direction, never action identifiers** | chaining `action_id`s directly | **Decided on 2026-08-26.** Almost everything in Star Citizen is a toggle: a macro chaining raw identifiers would chain toggles, and every step would be a coin flip depending on the ship's state — a five-step sequence would have one chance in thirty-two of succeeding. By naming `command_id` + `polarity`, every step inherits the polarity resolution (D33): a directed action when it has a key, falling back to the toggle otherwise |
| **D38** | **References are expanded before the guard**, never during execution | resolving each step as the sequence reaches it | **Decided on 2026-08-26.** A macro whose fifth step has no shortcut would otherwise play the first four and then stop, leaving the ship in an intermediate state nobody asked for — power on, doors open, no shields. The guard therefore checks the whole sequence before a single press leaves, and names the offending action: out of ten steps, knowing **which** one is missing is the whole difference between a diagnosis and a riddle |
| **D39** | **The grammar receives the accented text**, while the lookup table keeps the normalised form | building the grammar from normalised text | **Measured in flight on 2026-08-26.** A grammar engine derives the expected pronunciation from the text it is given: “prepare le decollage” is modelled as “pre-pare le de-collage”, two wrong syllables in French. Confidences recorded: 0.41 to 0.67 for that phrase, against 0.87 and above for commands whose loss of accents changes little in pronunciation. Matching, on the other hand, stays accent-insensitive — normalisation happens after recognition. 75 catalogue phrasings re-accented |
| **D40** | **A macro step can require a guaranteed direction** (`require_directed`) and be skipped rather than fall back on a toggle | applying the fallback everywhere, or forbidding it everywhere | **Observed in flight on 2026-08-26**: “prep for takeoff” **opened** the doors instead of closing them. The game exposes no direction for `v_toggle_all_doors`, so the step fell back on the toggle and did the opposite half the time. Forbidding the fallback everywhere would have emptied macros of their substance — powering up a cold ship through a toggle is exactly what you want. The judgement therefore belongs to the data, not to the engine: the flag goes only on the steps whose starting state is uncertain. A skipped step appears in the trace with its reason — a macro that silently skips a step lets you believe it did everything |
| **D41** | **Doors and flight mode go through the game's directed actions** (`v_open_all_doors`, `v_close_all_doors`, `v_master_mode_set_nav`, `v_master_mode_set_scm`) | watching the pilot's keystrokes to guess the state | **Corrected on 2026-08-26, on the maintainer's report.** I had concluded the game exposed no direction for these two commands, and considered watching the keyboard to reconstruct the state — at exactly the cost of the compromise that got us blocked by Smart App Control. The conclusion was wrong: my search filtered on the `_on`/`_off` suffixes, and those actions do not carry them. They exist, simply with no default key. Flight mode and doors therefore become **deterministic** as soon as the pilot assigns them a key, with nothing to observe and nothing to assume. The lesson goes beyond this file: read **and** write with newline translation disabled, or in bytes. The 406 lines are normalised |
| **D84** | **The interface speaks the mobiGlas's visual language** | keeping a generic dark desktop theme | **Requested by the maintainer on 2026-08-28, from a screenshot of the game.** Optimus gets looked at between two manoeuvres, with the eye still in the cockpit: changing visual register every thirty seconds costs a second of adjustment on each round trip. The language holds in four rules — a nearly black background tinted blue, one-pixel strokes in cold cyan, **brackets at the corners and never rounded ones**, one colour per meaning. It all lives in `App.xaml`: the views only had to change by one word. Three choices are worth noting. **The echo** on the labels — that offset, nearly extinguished double, the game's signature — is a drop shadow with no blur, which avoids duplicating the text across thirty views. **The frame** is a `ContentControl` and not a `Border`, the only way to overlay the brackets on the stroke; it had to be given both “Stretch” alignments, without which it shrank what the `Border` stretched. **Letter spacing**, on the other hand, does not exist in WPF — it is a WinUI property. The breathing room therefore comes from Bahnschrift, the DIN shipped with Windows 10, guaranteed present since the installer already requires 10.0.19041 |
| **D85** | **The title bar is darkened with `DwmSetWindowAttribute`** | leaving it to the system theme | **Observed on screen on 2026-08-28.** A white band capped an entirely black window: the only dazzling thing on the screen, and it broke the illusion of an instrument panel outright. WPF exposes nothing for this — the bar belongs to the window manager, not to the application. The call is made on `SourceInitialized`, the only moment when the handle already exists but the window is not yet painted; earlier there is no handle, later the bar flashes light. The failure is silent and harmless: on a Windows earlier than 20H1 the attribute does not exist, the bar stays light, and nothing else changes |
| **D27** | **The game's path read through `QueryFullProcessImageName`**, never through `Process.MainModule` | the usual .NET API | Observed in game on 2026-08-25: `MainModule` fails on Star Citizen even though the game is not elevated — the anti-cheat refuses the rights it demands. `QueryFullProcessImageName` makes do with `PROCESS_QUERY_LIMITED_INFORMATION`. Without that path there is no channel, and therefore no automatic keybind import and no access to `Data.p4k` |
| **D26** | **Default STT model: `base`**, threads = the number of **logical** processors | `small` “for accuracy”, `tiny` “for speed” | Measured (S0-2): `small` is no more accurate than `base` on our vocabulary (10.4% against 9.8% WER) for 3.4× the time; `tiny` collapses to 59.4% and misses the wake word. SMT brings a real gain (8 threads > 6 > 4), contrary to intuition |
| **D23** | **Warming the speech engines at startup** (one empty synthesis, one STT model load) | lazy initialisation | Measured (S0-5): the first synthesis costs up to **429 ms** against 7 to 15 ms afterwards. Without a warm-up it is Optimus's very first answer — the one that makes the first impression — that would be the slowest |
| **D24** | **The audio capture stream stays open permanently**, with a pre-roll ring buffer | opening the microphone when PTT is pressed | Measured (S0-3): opening the device costs **419 ms**. Opening on demand would lose the start of every sentence — the leading cause of recognition failure |
| **D25** | **`INSERT` as the default PTT key** | `F10` | `F10` already carries `v_power_throttle_up` and `v_power_throttle_max` in Star Citizen (checked against `defaults-4.9.json`) |
| **D22** | **A probe or an input component must never be able to kill the process**: message loop and native callbacks wrapped, delegates kept alive, a window class with a unique name | letting exceptions propagate | Lived through during the spike: a window class with a fixed name reused on the second launch inside the same process caused a native exception that killed PowerShell. `Optimus.Infrastructure.Input` will use the same mechanisms, with a far longer lifetime |

## 13.5 Points for you to settle

| Subject | Options | Recommendation |
|---|---|---|
| **Product name** | keep “Optimus” / rename the product and keep Optimus as the default copilot | Settle before any public distribution; no technical impact |
| **Kill switch shortcut** | `F12` (taken in SC: *Toggle Chat Window*) / `Ctrl+Alt+Pause` / `Ctrl+Alt+K` | **`Ctrl+Alt+Pause`** — impossible to trigger by accident, unused by the game |
| **PTT key** | ~~`F10`~~ / `INSERT` / `RCTRL` / a side mouse button | **`INSERT` by default.** `F10` is to be avoided: going through `defaults-4.9.json` shows it already carries `v_power_throttle_up` and `v_power_throttle_max`. Of the 81 keys Star Citizen uses, these stay free: `INSERT`, `DELETE`, `RCTRL`, `RSHIFT`, `PAUSE`, `SCROLLLOCK`, `NUMLOCK`, `NP_ENTER`, `F13`–`F15` |
| **Language of the shipped catalogue** | FR only / FR+EN | FR first (your own use), with the i18n structure in place from the start |
| **Distribution** | private / open source / product | **Leaning towards open source since 2026-08-27**, and for a concrete rather than doctrinal reason: it is the only route that makes code signing free (the SignPath Foundation, R16), the others costing €100 to €600 a year. Still to settle formally — opening the repository also commits to a licence and to what you accept seeing contributed to it |
| **Default Whisper model** | `base` (fast) / `small` (accurate) | Decided by the S0-2 spike benchmark, not in advance |
